# 2026-09-27

## Mobile responsiveness + SEO pass on `Frontend` (Next.js 16 App Router)

### Mobile fixes
- Added a **"MOBILE APP EXPERIENCE LAYER"** section at the end of `app/globals.css`.
  All rules are scoped behind `max-width: 767px/900px` media queries so desktop is untouched.
  Covers: overflow guards, 44px touch targets, 12–14px type floor, 16px form inputs
  (stops iOS zoom-on-focus), safe-area insets, momentum scrolling, drawer body-lock,
  `backdrop-filter` removal for scroll smoothness, `prefers-reduced-motion`.
- **`/help`, `/policy`, `/career` etc.** — `UsefulLinksPageClient` had a hardcoded
  inline `gridTemplateColumns: "280px 1fr"` with no breakpoint, which clipped the
  main column off-screen on phones. Replaced with a `.ul-page-grid` class that
  collapses to one column and moves the sidebar *below* the article. The inner
  `repeat(3, 1fr)` card grids became `.ul-card-grid` (3 → 2 → 1 columns).
- **`/messages`** — `.message-header` was a fixed-width flex run ~3180px wide, so
  every contact name after the first was clipped and labels overlapped. Made it a
  horizontal scroll-snap strip with 68px avatars and ellipsised names.
- Verified with a Playwright harness at 375/390/412px (scripts kept in `.workbuddy-ai/tmp`).

### Performance
- **Icon font: 525KB → 25.9KB (-95%).** The app used 154 of 2095 icofont glyphs.
  `scripts/subset-icofont.py` extracts the used classes, subsets the woff2 and
  generates `public/css/icofont-subset.css`.
- `scripts/strip-icofont-from-bundle.py` removes the bundled @font-face + 2095 glyph
  rules from `public/css/main.min.css` (**429KB → 342KB**), backup at `.bak`.
  `icofont-subset.css` must load *after* `main.min.css` (see `app/layout.tsx`).
- Fixed 5 icon class names that did not exist in icofont and rendered as blanks:
  `icofont-android`→`brand-android`, `behance-original`→`behance`,
  `eye-alt-alt`→`eye-alt`, `shield-check`→`shield-alt`, `shopping-bag`→`bag-alt`.

### SEO
- **`app/post/[id]/page.tsx`** — new server-rendered public post pages. These are
  the platform's main indexable content (Facebook/TikTok style). Includes
  `SocialMediaPosting` JSON-LD, canonical, OG/Twitter cards, breadcrumb.
- **`app/sitemap.ts`** is now async and includes every public post (58 URLs vs 24 static).
- `app/robots.ts` — added disallows for `/messages`, `/profile`, `/payout`, `/search`,
  and allow rules for image/video/ads bots.
- **`components/seo/SeoContentSection.tsx`** — reusable server-rendered content block
  (h1 + copy + feature list + FAQ + internal links + `FAQPage`/`BreadcrumbList` JSON-LD).
  Added to `/videos`, `/products`, `/books`, `/help`. **No page previously had an `<h1>`.**
- `app/manifest.ts` (PWA: standalone display, shortcuts, maskable icon) and real icons
  generated into `public/icons/` + a 1200x630 `og-image.png`.

### Known constraint (not fixed — needs a product decision)
`components/auth/RequireAuth.tsx` returns `null` server-side, so every gated route
(`/`, `/groups`, `/courses`, `/events`, `/blog`, `/nearby`, `/pages`, `/world-tour`,
`/friends`, `/profile`, `/messages`, `/posts/[postId]`) ships **empty HTML** to
Googlebot. Real SEO for those needs either public preview pages or SSR content
outside the auth boundary. The `SeoContentSection` approach is the interim answer.
