Developer Guide

The project follows a clear split between API, persistence, and UI layers.

Backend Structure

src/
  app.ts
  server.ts
  socket.ts
  config/
  controllers/
  interfaces/
  middlewares/
  models/
  repositories/
  routes/
  services/
  utils/
  validators/
  • controllers/ handle HTTP input and response formatting.
  • services/ contain chat workflows and business logic.
  • repositories/ isolate MongoDB access.
  • socket.ts handles realtime delivery and read receipts.

Frontend Structure

client/src/
  app/
  components/Chat/
  lib/
  redux/
  • app/ contains the Next.js routes.
  • components/Chat/ contains the inbox workspace UI.
  • redux/features/auth manages login and stored credentials.
  • redux/features/chat uses RTK Query for conversations and messages.

Customization Points

  • Change API URLs with frontend environment variables.
  • Change allowed browser origins with FRONTEND_URL.
  • Adjust pagination in chatApi.tsx and controller defaults.
  • Extend the inbox UI from src/components/Chat/ChatApp.tsx.

Notes for Extending

  • Add new endpoints in routes/, then wire them to a controller and service.
  • Add new realtime events from the backend with emitToUser in socket.ts.
  • Prefer env-driven configuration instead of hardcoded hostnames or secrets.
